# Security Policy

## Supported Versions

Only the latest major release of Orix X receives security updates and patches. We recommend updating as soon as possible when a new version is released.

| Version | Supported          |
| ------- | ------------------ |
| 2.0.x   | :white_check_mark: |
| < 2.0.0 | :x:                |

---

## Reporting a Vulnerability

We take the security of Orix X and projects generated by it very seriously. If you discover a security vulnerability, please do not disclose it publicly.

Instead, please report it via one of the following methods:
- Email `security@kryonara.com` with a detailed description of the vulnerability, reproduction steps, and potential impacts.
- Submit a draft security advisory via GitHub under the Security tab of the repository.

Our security team will acknowledge receipt of your report within 48 hours and provide a status update on patching timeline.

---

## Security Best Practices for Templates

- **No Secrets in Templates**: Never commit active API keys, JWT secrets, or DB passwords to templates. Use environment variable placeholders (`{{ secret_key }}` or `os.getenv`).
- **Dependency Version Pinning**: Ensure package templates have safe, updated ranges of dependencies to avoid downstream supply-chain attacks.
