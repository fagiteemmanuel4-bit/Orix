# Orix Competitive Matrix

This document provides a highly technical comparative analysis of Orix against leading industry and open-source AI coding agents.

| Capability | Orix (P0.7) | OpenAI Codex / GPT-4 | Claude Code | OpenHands / SWE-agent | Aider | Best Approach |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Context Size Management** | Slices symbols using AST; trims token histories dynamically. | Relies on model token allocation; no smart local slicing. | Extremely large context cache; costly on long logs. | Sends massive multi-file trees; lacks local AST slicing. | Adds files explicitly; parses git diff context maps. | **Orix**: Slices context precisely at symbol level using AST. |
| **Tooling Gating & Verification** | Mapped permission tiers (READ_ONLY, SAFE, etc.); auto pytest verification. | Direct execution or manual copy-paste; no gate controls. | Prompts for terminal commands; no multi-tier gating. | Runs in Docker; limits host mutations but has heavy dependencies. | Integrates with git; relies on developer review. | **Orix**: Combines sandboxed execution with automated local verification. |
| **Model Independence** | Agnostic adapter contracts (OpenAI, Anthropic, Gemini, Ollama, etc.). | Locked to OpenAI models and APIs. | Locked to Anthropic Claude models. | Supports multiple APIs; complex setup. | Supports many models; command-line key driven. | **Orix**: Built-in Model capability registry with failover fallbacks. |
| **Cost Control** | Built-in `orix cost` tracking and dynamic task routing (cheap vs reasoning models). | No built-in cost tracking or estimates; relies on billing panels. | High context cost without dynamic complexity routing. | Massive multi-agent loops can run away with budget. | Command line reports token usage; no routing options. | **Orix**: Automatically routes tasks based on complexity and counts costs locally. |
| **Offline Execution** | Seamless local fallback routing to Ollama/llama3 on remote failures. | Requres 100% remote connectivity. | Requres 100% remote connectivity. | Supports local models but requires heavy Docker/agent setups. | Supports Ollama via lite-llm configurations. | **Orix**: Zero-overhead local failovers with built-in status detection. |
| **Security Controls** | Sandboxed toolbox, path traversal defense, and symlink/shell injection protection. | Copy-paste only; no active boundary protections. | Command confirmation prompts; lacks symlink hardening. | Secure because it runs inside a virtual Docker machine. | No sandboxing; writes directly to local directory. | **Orix**: Complete local toolbox path-protection and shell-safe boundaries. |
